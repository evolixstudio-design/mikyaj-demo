# Release checklist — 6 October 2026

The owner explicitly authorized Skinlite removal, cache/performance updates and pushing the reviewed site to GitHub on 5/6 October. This supersedes earlier local-preview-only restrictions in the handoff. Do not expose `.env`, local database backups, customer/order data or test accounts in production.

## Changes

- Every product has Arabic/English “How to use”. Clearly labelled source instructions are separated into that section. Products without supplied instructions show an honest packaging/help fallback, not invented product advice. Admin editors have dedicated bilingual directions fields.
- Shared admin toolbar includes Refresh on all management pages; the existing unsaved-edit warning still applies.
- Versioned CSS/JS URLs, revalidation headers, bundled/minified release scripts and both minified stylesheets. Brotli is supported by the existing compression middleware; APIs containing private information remain `no-store`.
- Soft-delete confirmed Skinlite products, preserving historical order references. Confirmations are recorded in `docs/skinlite-removal-review.json`. OCR is a candidate-finding aid, not a guarantee of identifying illegible packaging text.
- Transfer only approved public catalog descriptions, translations, brand links and taxonomy images. No preview accounts, transactions, settings, prices, stock quantities or unrelated test visibility changes are transferred.

## Data transfer and recovery

The local public catalog backup is `.local-test-data/pre-release-public-backup.json`. The reviewed transfer manifest is `.local-test-data/catalog-release.json`; both are ignored by Git. Use `scripts/apply-reviewed-catalog.cjs --file=<manifest>` for a rollback-only dry run, and add `--apply` to commit. It matches product slugs, original Arabic names and baseline/source hashes, and protects REVIEWED copy. Existing product-brand links are preserved. Each original affected product/taxonomy row is retained in `catalog_release_backups` inside the same transaction. The release ID groups recovery rows. Do not blindly restore full historical rows over newer purchases or editorial changes; restore only the changed descriptive/image/visibility fields after review.

Apply schema migration 020 before running the new backend. Render's repository configuration includes migration execution before startup, but actual hosted commands and automatic-deploy settings must be verified independently.
